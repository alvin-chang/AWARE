## Bug fix summary

Two related bugs were causing the coordinator to fail in production:

1. **Items 18/19 root cause** (`src/coordinator/heavyskill-integration.js:16` +
   `src/coordinator/plugin-config.js:29`): both files used a static
   relative import `'../../../heavy-think/src/index.js'` that resolved to
   `/heavy-think/...` in the Docker image (where `WORKDIR=/app`),
   ignoring the `AWARE_HEAVY_THINK_PATH` env var the Dockerfile sets.
   The coordinator crash-looped on
   `ERR_MODULE_NOT_FOUND: /heavy-think/src/index.js` at every boot.

   Fix: both modules now resolve heavy-think lazily via
   `config.heavyThink.path`. No top-level await (preserves
   CJS-`require()`-compatibility for `rate-limit.test.js`).

2. **Auth path crash** (`src/coordinator/http-server.js:184`):
   `_rateLimitKey()` called `require('node:crypto')` inside an ESM
   module. The runtime is ESM (`package.json type=module`) so `require`
   is undefined. When a request carries an Authorization header, the
   rate-limit key code path runs and crashes with
   `ReferenceError: require is not defined`, returning an internal
   error envelope instead of the coordinate result.

   Fix: import `createHash` from `node:crypto` at module top and use
   it directly (no `require()`).

Both fixes verified by:
- `npm test` — 469/469 passing
- Live bring-up — coordinator healthy, /coordinate returns a result envelope
- `test/integration/coordinator-bring-up.test.js` — added regression
  gate; SKIPs by default (gated on `AWARE_BRINGUP_OK=1`) so the unit
  test suite stays fast.
