## What was NOT changed (and why)

1. **`metaclaw` directory name in code paths** — `src/config/index.cjs`, `src/coordinator/heavyskill-integration.js`, `test/unit/coordinator/heavyskill-integration.test.js` retain `~/.metaclaw/preference-pairs/` as the default filesystem path. Renaming this would break the user's existing deployment. Documented as a known public disclosure (a project name), not a secret.

2. **`LLM_API_KEY` env var name** — kept verbatim because it's what `src/config/index.cjs:163` actually reads. Operators who set this var already know the name.

3. **`'orchestrator'` as a generic role string** in `pathAgents` arrays, `criticalRoles`, `permission-model.js`, `server.js` — these are functional role identifiers in routing/permission code, not references to a private agent literally named "Orchestrator". "Orchestrator" is an English word describing a coordinating role.

4. **The v1 demo's `mockAgents` display names** — replaced (see above), but the `id`/`agentId` strings like `agent:coder:demo-002` are now generic role names rather than `agent:forge:live-002`.

5. **Test fixtures describing what the privacy filter blocks** (`~/.aws/`, `~/.ssh/`, `192.168.x.x`, `10.x.x.x`) — these are **deliberately** in test files to verify the privacy filter catches them. Removing them would defeat the test's purpose.
