## Pattern: confidence-vs-honesty trade-off

Examining the actual reasoning text from a few inverted pairs (extracted during ADR-028 Finding 1):

**Pair 0 (inverted, gap=−0.05): "What is AWARE 2.0?"**
- **chosen** (lower score, 0.75): explicit hedging — "specifics vary by release and should be verified against the official repository"; "ambiguity caveat (Step 1)"
- **rejected** (higher score, 0.80): confident assertion — "Laravel/PHP, MySQL/MariaDB, Apache 2.0 license, MQTT"

**Pair 1 (inverted, gap=−0.40): "Reply with the single word: hello"**
- **chosen** (lower score, 0.60): presumably the refined attempt (likely with extra context/wrapper text)
- **rejected** (higher score, 1.00): exactly "hello" — perfect compliance

**Hypothesis:** The PRM judge prompt is:

> "Score the agent's reasoning on a scale of 1-10. Focus on REASONING PROCESS, not outcome. A correct answer reached by flawed reasoning should score low."
> "1-3: Flawed logic, hallucination, irrelevant or circular reasoning"
> "7-8: Strong reasoning, clear structure, addressed main cases"
> "9-10: Excellent, anticipates edge cases, self-corrects, justified claims"

The judge is **scoring reasoning process correctly** under this rubric — confident, structured, "anticipates edge cases" responses do score higher than hedged responses. But the **selection logic** at `~/src/heavy-think/src/index.js:101`:

```javascript
const bestInitial = [...scored].sort((a, b) => b.prm_score - a.prm_score)[0];
```

selects the **highest-PRM-score** attempt as "best." When PRM rewards confident hallucination, "best" is the hallucinated answer. The refinement step then builds on top of the hallucinated attempt, but the refinement often adds hedging (correct behavior), which PRM then scores lower.

**The result:** chosen.prm_score (refined) is consistently lower than rejected.prm_score (unrefined) because the refinement is doing its job (correcting hallucinations) but the PRM judge is scoring the unrefined hallucination higher.

---

## Root cause analysis

Three possible root causes, listed in order of likelihood:

**A) PRM judge rubric rewards confident hallucination** (most likely). The rubric's "Strong reasoning, clear structure" language and "9-10: Excellent, anticipates edge cases" encourages confident detail. Hedging language ("may", "might", "unverified") is implicitly penalized.

**B) Selection logic uses PRM score as "best" criterion** (likely). The selection is "highest PRM score = best," but if PRM is rewarding confidence, "best" is the confident hallucination.

**C) Refinement adds hedging that PRM penalizes** (contributing factor). The refinement step is correctly identifying hallucinations and softening them, but the softening lowers the PRM score.

All three contribute. Fixing any one without the others may not resolve the inversion.

## Fix surface analysis

The three potential fix points are all in `~/src/heavy-think/`:

| Fix surface | File | Lines | Effort | Risk |
|---|---|---|---|---|
| Re-prompt PRM judge with anti-hallucination clause | `prm.js` | 16-26 (DEFAULT_PRM_PROMPT) | Low (one prompt edit) | Medium (might shift PRM scoring unpredictably across all consumers) |
| Modify selection to use lowest-PRM-score | `index.js` | 101 | Low (one line) | High (assumes inversion always; could break correct cases) |
| Modify refinement to preserve PRM-positive features | `refine.js` | full file | High (algorithmic change) | Medium |
| Detect inversion post-hoc and swap labels | `index.js` (Stage 6) | 122-135 | Low (~10 lines) | High (assumes inversion always; if PRM is fixed, this corrupts correct pairs) |
| Add `prm_inverted` flag to pair record (don't fix, just signal) | `index.js` | 122-135 | Low (~5 lines) | Low (informational only; lets downstream decide) |

**Recommended fix path (initial proposal, subject to Archimedes review):**

1. **Re-prompt PRM judge** (Fix A) with explicit anti-hallucination clause:
   - Add to DEFAULT_PRM_PROMPT: "Penalize confident assertions that lack grounding. Hedging language is preferred over unfounded specifics. A correct answer reached by acknowledging uncertainty should score HIGHER than an incorrect answer reached by confident hallucination."
   - Estimated effort: 1-line prompt edit + 1 unit test for the new prompt.
   - Risk: the model may shift its scoring in unexpected ways for non-AWARE consumers of heavy-think. Mitigation: make the change opt-in via `prmConfig.system_prompt` override, with the new prompt as the AWARE-specific override.

2. **A/B test the new prompt** on the existing 23 pairs (re-run with cached or new pairs) to measure inversion rate drop.
   - If inversion drops to <10%: prompt change is sufficient. Move to Repair 3 closeout.
   - If inversion stays high: combine with Fix B (modify selection) or Fix D (flag, don't fix).

3. **Add `prm_inverted` flag to pair record** (regardless of Fix A outcome) as informational signal. This is a 1-line code change + 1-line test.

## Calibration methodology (for ADR-030's name)

This section proposes the ongoing methodology, not just this turn's audit:

**Daily calibration check:**
- Run a 5-problem standard probe (factual Q&A, no edge cases) at session start
- Compute inversion rate on the 5 produced pairs
- If inversion rate > 50%: alert (PRM regression — possible model drift)
- If inversion rate 10-50%: warn (PRM may be borderline)
- If inversion rate < 10%: pass (PRM is well-calibrated)

**Weekly calibration study:**
- Same as today's n=23 study but on a larger batch (≥30) across all task_types
- Output: a JSONL file at `~/src/AWARE/eval-results/prm-calibration-<date>.jsonl` with per-pair (gap, task_type, problem, content_hash)
- Threshold for "PRM healthy": ≤10% inversion rate across the sample

**PRM scoring rubric update cadence:**
- Quarterly: review `DEFAULT_PRM_PROMPT` for rubric drift
- Annual: full PRM judge model evaluation (compare with/without prompt against a held-out test set)

**Pair acceptance criteria (post-Fix):**
- `outcome-filter.js` `min_score_gap` rule (now strict by default after Repair 1) drops any pair with gap ≤ 0
- After Fix A: inversion rate should drop, so more pairs survive the filter
- Directionality check (Repair 1) remains as a defense-in-depth gate regardless of PRM health
