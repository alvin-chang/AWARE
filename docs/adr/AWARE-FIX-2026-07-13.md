# AWARE-FIX-2026-07-13 — ADR Numbering Collision

This document is the historical record of the 2026-07-13 ADR numbering
collision and its fix. It is the **only place outside `scripts/pre-commit-check.sh`**
where the literal string `ADR-044` may appear in the AWARE repo going
forward; the pre-commit check's stale-ADR-044 rule explicitly exempts
this file.

## The incident

On 2026-07-13, three ADRs were drafted in a 5-minute window
(12:29–12:34 BST) and all three claimed the number ADR-044:

1. **ASI06 (OWASP Agentic AI Security Top 10: ASI06 / Memory Poisoning)**
   — saved as `ADR-044-asi06-coverage.md`
2. **AISVS (OWASP AI Security Verification Standard)** — saved as
   `AISVS-coverage.md` (no number prefix at all)
3. **MITRE ATLAS v2026.06** — saved as `ADR-044-aware-atlas-v2026.06-coverage.md`

There is no ADR number allocator. Numbering is by-hand: pick the next
free number, name the file, save. In a single task drafting three ADRs,
this is exactly the kind of coordination failure the convention was
vulnerable to.

## Initial fix

The three files were renamed:

- `ADR-044-asi06-coverage.md` → `ADR-045-aware-asi06-coverage.md`
- `AISVS-coverage.md` → `ADR-046-aware-aisvs-coverage.md`
- `ADR-044-aware-atlas-v2026.06-coverage.md` → `ADR-047-aware-atlas-v2026.06-coverage.md`

The renumbering is by **completeness**, not chronology:

- **ADR-045** = ASI06 — has the most-shipped artifacts
  (`asi06-catalog.js`, `asi06-mapper.js`, `amg-client.js`)
- **ADR-046** = AISVS — also has shipped artifacts
  (`aisvs-catalog.js`, `aisvs-checklist-bridge.js`)
- **ADR-047** = MITRE ATLAS — has the catalog (`atlas-catalog.js`)
  but no `atlas-mapper.js` yet (proposal only)

After renaming, all internal `ADR-044` self-citations and source-file
references were sed-replaced with the new number. AST10 (ADR-043) was
unchanged.

## Why the initial fix was incomplete

A first-pass verification sweep was done with `head -10` truncation,
which hid several misses:

- `src/compliance/atlas-mapper.js` — 17 references, all should be
  ADR-047 (sed left them at ADR-045 due to a sed-pipeline bug)
- `src/compliance/framework-mapper.js` — 14 references, all should
  be ADR-047
- `src/policies/tool-observation-proxy.js` — 1 reference, should
  be ADR-047
- `src/compliance/aisvs-checklist-bridge.js` (test) — 8 references,
  should be ADR-046
- `docs/adr/ADR-046-aware-aisvs-coverage.md` — 3 self-references
  to the old `AISVS-coverage.md` filename (broken by the rename)

The lesson: **for destructive renames, the verification grep has no
`head` cap.** The full output is cheap; missing a real reference is
expensive.

## The gate (the durable fix)

A new pre-commit check was added to `scripts/pre-commit-check.sh`
that enforces ADR-numbering at commit time. The check fires on:

1. **Filename uniqueness** — no two files in `docs/adr/` may share
   the same `ADR-NNN` prefix.
2. **Filename pattern** — every ADR file must match
   `ADR-NNN-<slug>.md`. Un-numbered docs (positioning memos, etc.)
   can opt out with a `**ADR-number: skipped**` marker in the first
   3 lines of front matter.
3. **H1 / filename consistency** — the `# ADR-NNN` H1 must match
   the ADR-NNN in the filename.
4. **Stale-name check** — staged content must not reference the
   old un-prefixed filename (e.g. `AISVS-coverage.md`).
5. **Stale-number check** — no file in the working tree (excluding
   the check script itself and this fix-history doc) may contain
   the string `ADR-044`.

The check runs in ~1 second on the AWARE repo and fires before the
existing privacy-filter checks. The hook is installed by
`scripts/install-hooks.sh`, which the operator runs after pulling
this change.

## Test matrix

The check was validated against six scenarios before merging:

| Scenario | Expected | Result |
|----------|----------|--------|
| Clean state | pass | ✅ exit 0 |
| Duplicate `ADR-NNN` (two files share a number) | fail | ✅ exit 1 |
| Stale `ADR-044` in `src/` | fail | ✅ exit 1 |
| Un-prefixed filename, no opt-out | fail | ✅ exit 1 |
| Un-prefixed filename with `ADR-number: skipped` opt-out | pass | ✅ exit 0 |
| H1/filename mismatch | fail | ✅ exit 1 |

## Author-side rules (in CONTRIBUTING.md §"Creating a new ADR")

The check enforces the convention at commit time, but authors need
to know the rules at *draft* time. CONTRIBUTING.md §"Creating a new
ADR" lists:

1. Find the next free number with
   `ls docs/adr/ | grep -oE "ADR-[0-9]+" | sort -V | tail -1`
2. Use the pattern `ADR-NNN-aware-<short-slug>.md`
3. H1 must be `# ADR-NNN — <Title>`, number matches filename
4. For un-numbered docs, add `**ADR-number: skipped**` in the
   first 3 lines of front matter
5. For renames, sed-replace the OLD ADR-NNN across `docs/adr/`,
   `src/`, and `test/` in a single pass

## Why this file is exempt

The pre-commit check's stale-ADR-044 rule exempts this file and the
check script itself. The exemptions are necessary because:

- The check script's error message and comments reference ADR-044
  as the historical collision number
- This file is the canonical record of the incident; rewriting it

Any other reference to `ADR-044` in the repo after this commit is a
regression and will block the next commit.
